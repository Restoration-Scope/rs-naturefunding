Grant workflow

Four stages: Discovery fills a backlog, Gathering collects the intel, Triage validates each entry, Processing gives operators the evidence to decide.

The four stages

Discovery fills a backlog; Gathering collects everything later steps need; Triage validates each entry; Processing turns the evidence into what an operator needs to make the call. Keeping current re-reads what is listed. Today Gathering runs only after a listing exists (inside the requirements pipeline); the target is to gather before Triage, so Triage decides on the full picture. Green: code that decides. Blue: an outside API or model is called, or not built yet (“Next”). Amber: a person or agent decides. Red: left out. Purple: a file or record. Solid arrows: flow and writes; dotted: reads; two heads: reads and writes.

1. Discovery: fill the backlog

Two jobs in refresh.yml raise leads; none becomes a listing by itself. No model is called here: the EU and grants.gov searches are keyword APIs and Exa is a search engine. The backlog is the open discovery issues. Functions: isNbsEuTopic, isNbsUsOpportunity, organisationLead, newCandidates and fileDiscoveryIssue in scripts/refresh/discover.ts; newLeads in scripts/refresh/discover-web.ts. Green: code that decides. Blue: an outside API or model is called, or not built yet (“Next”). Amber: a person or agent decides. Red: left out. Purple: a file or record. Solid arrows: flow and writes; dotted: reads; two heads: reads and writes.

2. Gathering: collect the intel

Built today as stages 1–2 of the requirements pipeline (scripts/requirements/), for listed programmes only. Next: run it for each backlog lead before Triage, and widen it from the call’s rules to everything an applicant meets: the form itself, FAQs, earlier rounds, launch posts and who got funded. What it finds is evidence for later stages, never a fact by itself. Functions: queue in queue.ts; seedsOf, gather, politeReader, linksFrom, classifyLink (RELEVANT, NOISE), lowTextPdf, BOUNDS in gather.ts; the about-check calls Jev. Colours and arrows as in 1.

3a. Triage: decide

No script yet: an agent session or Bernat reads each lead and its gathered pages against docs/triage-criteria.md. Colours and arrows as in 1.

3b. Triage: write and validate the listing

An agent writes the file from the funder’s own page; every gate after that is code. There is no CI on pull requests, so the agent runs bun test, check and build before it commits. Functions: checkData in src/data/load.ts; statesYear and statesDate in src/data/schema.ts; deadlinePassed in scripts/refresh/deadline.ts; fetchPage in scripts/data/page-text.ts; quoteOnPage in src/data/text.ts. {id} is the programme id. Colours and arrows as in 1.

4a. Processing: read what it takes to apply

Stages 3–8 of the requirements pipeline, on what Gathering collected. Code owns the workflow and every check it can state; models only read language. One programme at a time, ~30 per pull request. Functions: chunksOf, extract, reconcile in extract.ts; verify, locate in verify.ts; check, omissions in check.ts; run in pipeline.ts; apply, manifest in write.ts.

4b. Processing: the applicant’s view

What we structure from the pages, and how it turns into a decision for one operator. “Next” marks what isn’t built yet.

5a. Keeping current: the daily read

scripts/refresh/run.ts, the “Read pages” step of refresh.yml, daily at 05:17 UTC. Tier A is code only and lands on main. Tier B goes to two models from different families on Cloudflare Workers AI and becomes a pull request (5b). Jev is not called anywhere in section 1; it checks requirements in Gathering and Processing. Functions: isDue and programmeChecks in state.ts; readPages in fetch.ts; classify and applyTierA in tier.ts (with quoteOnPage from src/data/text.ts and deadlinePassed from deadline.ts); extractAndReview and applyExtraction in tier-b.ts, models called through llm.ts; all under scripts/refresh/. {source-id} is the id in data/sources.json. Colours and arrows as in 1.

5b. Keeping current: landing and publishing

The rest of refresh.yml, its Monday 06:43 UTC weekly mode, and deploy.yml. Tier A commits go straight to main; every changed fact waits on a pull request. No refresh pull request has been merged so far: an agent session or Bernat checks them against the page and lands the good changes in batches on main, and the rest are closed as superseded. An open decision (20 Nov 2026) would commit clean drafts directly. checkLink is in weekly.ts; fiscal sponsors (sponsors.ts) are re-read there too, and a blocked page only shows in the summary; the commit step is in refresh.yml; deploy.yml runs hourly at :11. Colours and arrows as in 1.
